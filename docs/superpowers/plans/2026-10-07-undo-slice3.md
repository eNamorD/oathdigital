# Undo, Slice 3 (Redo) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A player who took back a step by mistake restores it with Redo, as long as no command has been accepted since. The restored lines rejoin the Game Log as if the undo had never happened.

**Architecture:**

- **Storage.** A new top-level event, `StepRestored(from, until, by)`, un-voids the range a `StepTakenBack` voided. It is journaled as `undo.step-restored`. Nothing is deleted or rewritten.
- **Fold.** `JournalFold` keeps a **redo stack** beside the live stack:
  - `StepTakenBack` moves the live stack's top onto the redo stack.
  - `StepRestored` checks the redo stack's top, moves it back onto the live stack, and sets the state to that batch's state after.
  - `CommandAccepted` empties the redo stack, whoever issued the command.
  - `logRevision` becomes the sequence of the latest marker of either kind.
- **Service.** `GameCommand.Redo(actor)` is handled beside Undo, before the walker-pending gate. It appends `StepRestored` for the redo stack's top when `actor` issued that batch. `LoadedGame` and `GameAccepted` carry a `redo: Option[UndoStep]` built the same way as `undo`.
- **Game Log.** The formatter treats a taken-back marker as standing until a later `StepRestored` lifts it. A restored batch is part of the live journal again, so its lines read exactly as before the undo and leave their taken-back group.
- **Wire and projection.** `GameIntent.Redo` (`"redo"`) binds to `GameCommand.Redo`. `GameProjection.redo: Option[StepOfferProjection]` is present only for the batch's issuer, with the note `Redo: {line}` or `Redo your last step`.
- **Frontend.** `UndoControl` becomes `StepControls`. It renders one `div.step-controls` row under the status line, holding Undo, Redo, or both, Undo first. Slice 2's log refetch already reacts to any `logRevision` change, so a redo refreshes every reader's log with no new client code.

```scala
import oathdigital.gameplay.setup.FirstGameSetupFixture.catalog
import oathdigital.model._

import oathdigital.testkit.Table
import oathdigital.testkit.Table.{p1, p2, p3}

/** The redo stack, as the service folds its journal (undo design, "Replay:
  * one forward fold" and "Redo"). Restore markers are written by journal
  * surgery here; the Redo command comes in its own suite. */
class JournalFoldRedoSuite extends munit.FunSuite:
  private val table = Table.start.banditsRefilled
  private def travel(actor: PlayerId, to: PlayerId) = GameCommand.StartWalker(
    ActionRef.Travel, StartPayload(actor, Vector.empty,
      Vector(DecisionOptionRef.Site(Table.quietPawnSite(to)))))
  private def accept(result: Either[GameApplicationError, GameAccepted])
      : GameAccepted = result.fold(error => fail(s"rejected: $error"), identity)
  private def range(step: UndoStep) = (step.issuer, step.from, step.until)

  /** `repository`'s game "g" as a fresh service loads it. */
  private def reloadedGame(repository: EventStreamRepository): LoadedGame =
    new GameApplicationService(catalog, repository, genesis = table.state)
      .load("g").fold(error => fail(s"load failed: $error"), identity)
      .getOrElse(fail("no game"))

  /** The journal index a fresh service's load of "g" fails at, if any. */
  private def replayFailureIndex(repository: EventStreamRepository)
      : Option[Long] =
    new GameApplicationService(catalog, repository, genesis = table.state)
      .load("g") match
      case Left(GameApplicationError.ReplayFailure(index, _)) => Some(index)
      case _ => None

  test("each undo offers its batch back, the latest undone on top"):
    val (service, _) = table.service()
    val first = accept(service.handle("g", 0L, travel(p1, p3)))
    val second = accept(service.handle("g", first.nextSequence, travel(p1, p2)))
    assertEquals(second.redo, None)
    val once = accept(service.handle("g", second.nextSequence,
      GameCommand.Undo(p1)))
    assertEquals(once.redo.map(range),
      Some((p1, first.nextSequence, second.nextSequence)))
    val twice = accept(service.handle("g", once.nextSequence,
      GameCommand.Undo(p1)))
    assertEquals(twice.redo.map(range), Some((p1, 0L, first.nextSequence)))
    assert(twice.redo.flatMap(_.note).nonEmpty,
      "a Travel posts a line its issuer sees")

  test("a new command batch empties the redo stack"):
    val (service, _) = table.service()
    val moved = accept(service.handle("g", 0L, travel(p1, p3)))
    val undone = accept(service.handle("g", moved.nextSequence,
      GameCommand.Undo(p1)))
    assert(undone.redo.nonEmpty, "the undone Travel waits to be restored")
    val again = accept(service.handle("g", undone.nextSequence, travel(p1, p2)))
    assertEquals(again.redo, None)

  test("a restore marker brings back its batch's state and its undo"):
    val (service, repository) = table.service()
    val moved = accept(service.handle("g", 0L, travel(p1, p3)))
    val undone = accept(service.handle("g", moved.nextSequence,
      GameCommand.Undo(p1)))
    val loaded = reloadedGame(UndoJournals.rewritten(
      UndoJournals.events(repository, "g") :+
        StepRestored(0L, moved.nextSequence, p1), "g"))
    assertEquals(loaded.state, moved.state)
    assertEquals(loaded.undo.map(range), Some((p1, 0L, moved.nextSequence)))
    assertEquals(loaded.redo, None)
    assertEquals(loaded.logRevision, Some(undone.nextSequence))

  test("a restore marker that does not name the latest undone batch fails replay"):
    val (service, repository) = table.service()
    val moved = accept(service.handle("g", 0L, travel(p1, p3)))
    val undone = accept(service.handle("g", moved.nextSequence,
      GameCommand.Undo(p1)))
    val events = UndoJournals.events(repository, "g")
    assertEquals(replayFailureIndex(UndoJournals.rewritten(
        events :+ StepRestored(1L, moved.nextSequence, p1), "g")),
      Some(undone.nextSequence))
    assertEquals(replayFailureIndex(UndoJournals.rewritten(
        events :+ StepRestored(0L, moved.nextSequence, p2), "g")),
      Some(undone.nextSequence))

  test("a restore marker after a new command batch fails replay"):
    val (service, repository) = table.service()
    val moved = accept(service.handle("g", 0L, travel(p1, p3)))
    val undone = accept(service.handle("g", moved.nextSequence,
      GameCommand.Undo(p1)))
    val again = accept(service.handle("g", undone.nextSequence, travel(p1, p2)))
    assertEquals(replayFailureIndex(UndoJournals.rewritten(
        UndoJournals.events(repository, "g") :+
          StepRestored(0L, moved.nextSequence, p1), "g")),
      Some(again.nextSequence))
```

```scala
/** The folded journal (undo design, "Replay: one forward fold"): the current
  * state, one step per event (markers included), the live stack (the
  * batches since the latest barrier, latest first) and the redo stack (the
  * batches taken back since the last command batch, latest first). */
final case class FoldedJournal(state: OathState,
    steps: Vector[ReplayStep[OathState, OathEvent]],
    live: List[CommandBatch], redo: List[CommandBatch] = Nil):
  def undoable: Option[CommandBatch] = live.headOption
  def redoable: Option[CommandBatch] = redo.headOption

  /** The sequence of the latest void marker: a client whose log predates it
    * must refetch the whole log (undo design, "Game Log"). */
  def logRevision: Option[Long] = steps.reverseIterator.collectFirst {
    case ReplayStep(RecordedEvent(index,
        _: StepTakenBack | _: StepRestored), _, _) => index }
```

```scala
  /** Taken-back moves (undo design, "Game Log"). The live entries are the
    * live journal formatted alone, so no line reads a voided event or a
    * marker. Each voided batch reads as it did before its undo: its entries
    * come from the live journal as it stood at its marker. That costs one
    * more formatting per standing marker. A restored batch is live again,
    * so its lines read as if it had never been taken back (undo design,
    * "Redo"). */
  def format(steps: Vector[ReplayStep[OathState, OathEvent]],
      viewer: Option[PlayerId]): Vector[LogEntry] =
    val markers = steps.indices.toVector
      .filter(at => isVoidMarker(steps(at).event.event))
    // The taken-back markers still standing before `end`, with their
    // positions. A restore lifts the latest one: the fold accepts a restore
    // only of the batch most recently taken back.
    def standing(end: Int): Vector[(Int, OathEvent.StepTakenBack)] =
      markers.takeWhile(_ < end).foldLeft(
          Vector.empty[(Int, OathEvent.StepTakenBack)]) { (stood, at) =>
        steps(at).event.event match
          case marker: OathEvent.StepTakenBack => stood :+ (at -> marker)
          case _ => stood.dropRight(1)
      }
    // The journal before `end`: no marker, and nothing a marker standing
    // there voids. Its positions then differ from its sequences.
    def live(end: Int) =
      val voids = standing(end).map(_._2)
      steps.take(end).filter { step =>
        val sequence = step.event.index
        !isVoidMarker(step.event.event) && !voids.exists(marker =>
          sequence >= marker.from && sequence < marker.until)
      }
    val stood = standing(steps.size)
    val voided = stood.flatMap((at, marker) =>
      formatLive(live(at), viewer).filter(entry =>
        entry.sequence >= marker.from && entry.sequence < marker.until))
    takenBack.mark(stood.map(_._2), (formatLive(live(steps.size), viewer) ++
      voided).sortBy(entry => (entry.sequence, entry.ordinal)))

  /** Whether `event` voids or restores a batch: it posts no line and is no
    * part of any journal a formatting reads. */
  private def isVoidMarker(event: OathEvent): Boolean = event match
    case _: OathEvent.StepTakenBack | _: OathEvent.StepRestored => true
    case _ => false
```

```scala
import oathdigital.protocol.{GameIntent => Intent}
import oathdigital.protocol.projection.StepOfferProjection
import org.scalajs.dom

/** The Undo and Redo controls (undo design, "Controls"): each shows only
  * when the projection offers the viewer that step, names it on hover, and
  * sends its intent. Both share one row under the status line. */
class StepControlsSuite extends munit.FunSuite:
  private val players = Vector(
    GamePlayer("red", "Red", "Exile", PlayerColor.Red),
    GamePlayer("blue", "Blue", "Exile", PlayerColor.Blue))
  private val undoOffer = StepOfferProjection("Undo: Travelled to Buried Giant")
  private val redoOffer = StepOfferProjection("Redo: Travelled to Great Spire")

  private def projectionOffering(undo: Option[StepOfferProjection],
      redo: Option[StepOfferProjection] = None): GameProjection =
    TestProjections.actingProjection(players = players)
      .copy(undo = undo, redo = redo)

  /** The panel as `presentation` sees it, with `controls` recording what
    * it submits. */
  private def panelFor(value: GameProjection,
      presentation: ServerUiSupport.ViewerPresentation,
      controls: RecordingControls, canControl: Boolean = true): dom.Element =
    ActionDecisionRenderer.actionsPanel(value, presentation,
      ParkedDecision.Routed(None, None), canControl, SessionDrafts.empty,
      controls).element

  private def buttonsMatching(panel: dom.Element, selector: String)
      : Vector[dom.html.Button] =
    panel.querySelectorAll(selector).toVector
      .map(_.asInstanceOf[dom.html.Button])

  private def undoButtons(panel: dom.Element) =
    buttonsMatching(panel, ".undo-action")
  private def redoButtons(panel: dom.Element) =
    buttonsMatching(panel, ".redo-action")

  private val waitingOnBlue = ServerUiSupport.ViewerPresentation(
    showGameplayControls = false, waitingForPlayerId = Some("blue"),
    waitingForDisplayName = Some("Blue"), playerId = "red")

  test("an offered step shows one Undo button whose hover note names it"):
    val panel = panelFor(projectionOffering(Some(undoOffer)),
      ActionPanels.actingViewer("red"), new RecordingControls())
    val buttons = undoButtons(panel)
    assertEquals(buttons.map(_.textContent), Vector("Undo"))
    assertEquals(buttons.head.title, "Undo: Travelled to Buried Giant")
    assert(!buttons.head.disabled)
    assertEquals(redoButtons(panel), Vector.empty)

  test("pressing Undo sends the Undo intent"):
    val controls = new RecordingControls()
    val panel = panelFor(projectionOffering(Some(undoOffer)),
      ActionPanels.actingViewer("red"), controls)
    undoButtons(panel).head.click()
    assertEquals(controls.submitted, Vector(Intent.Undo))

  test("an offered redo shows one Redo button whose hover note names it"):
    val panel = panelFor(projectionOffering(None, Some(redoOffer)),
      ActionPanels.actingViewer("red"), new RecordingControls())
    val buttons = redoButtons(panel)
    assertEquals(buttons.map(_.textContent), Vector("Redo"))
    assertEquals(buttons.head.title, "Redo: Travelled to Great Spire")
    assert(!buttons.head.disabled)
    assertEquals(undoButtons(panel), Vector.empty)

  test("pressing Redo sends the Redo intent"):
    val controls = new RecordingControls()
    val panel = panelFor(projectionOffering(None, Some(redoOffer)),
      ActionPanels.actingViewer("red"), controls)
    redoButtons(panel).head.click()
    assertEquals(controls.submitted, Vector(Intent.Redo))

  test("no offer, no row"):
    val panel = panelFor(projectionOffering(None),
      ActionPanels.actingViewer("red"), new RecordingControls())
    assert(panel.querySelector(".step-controls") == null, "no row expected")

  test("the actor waiting on another player's answer may still undo"):
    val panel = panelFor(projectionOffering(Some(undoOffer)), waitingOnBlue,
      new RecordingControls())
    assertEquals(undoButtons(panel).map(_.textContent), Vector("Undo"))

  test("Undo and Redo share one row directly under the status line"):
    val panel = panelFor(projectionOffering(Some(undoOffer), Some(redoOffer)),
      waitingOnBlue, new RecordingControls())
    val row = panel.querySelector(".status").nextElementSibling
    assertEquals(row.getAttribute("class"), "step-controls")
    assertEquals((0 until row.children.length).map(row.children(_).textContent)
      .toVector, Vector("Undo", "Redo"))

  test("while the connection is down both buttons are disabled"):
    val panel = panelFor(projectionOffering(Some(undoOffer), Some(redoOffer)),
      ActionPanels.actingViewer("red"), new RecordingControls(),
      canControl = false)
    assert(undoButtons(panel).head.disabled)
    assert(redoButtons(panel).head.disabled)
```

Replace the whole of `StepControls.scala` with:

```scala
package oathdigital.frontend

import oathdigital.protocol.{GameIntent => GameCommand}
import oathdigital.protocol.projection.StepOfferProjection
import org.scalajs.dom
import ServerUiSupport._

/** The Undo and Redo controls (undo design, "Controls"). The server offers
  * each step only to the player who may press it, so a control shows
  * whenever the projection carries its offer: in any phase, and while the
  * walker waits on another player. The labels are always "Undo" and "Redo";
  * each hover note names what the press would change. There is no keyboard
  * shortcut. */
private[frontend] object StepControls:
  def render(value: GameProjection, canControl: Boolean,
      submit: GameCommand => Unit): Option[dom.Element] =
    val controls = Vector(
      value.undo.map(control("Undo", "undo-action", _, GameCommand.Undo,
        canControl, submit)),
      value.redo.map(control("Redo", "redo-action", _, GameCommand.Redo,
        canControl, submit))).flatten
    Option.when(controls.nonEmpty) {
      val row = element("div", "step-controls")
      controls.foreach(row.appendChild)
      row
    }

  private def control(label: String, className: String,
      offer: StepOfferProjection, intent: GameCommand, canControl: Boolean,
      submit: GameCommand => Unit): dom.html.Button =
    val pressed = button(label, className)
    pressed.title = offer.note
    pressed.disabled = !canControl
    pressed.onclick = _ => submit(intent)
    pressed
```
